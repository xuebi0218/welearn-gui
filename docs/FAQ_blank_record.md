# 常见问题：跑完了，学习记录是空白 / 时长不涨

## 一句话结论

v3.8 会真实记录，并且能自己验证；旧版本出现"空白"，是三种不同故障的同一个表象 —— 它们都**没有真正写入时长或答题数据**，只写了一个"完成"状态位。

## 三种"空白"，看两列就能分清

对照平台课时列表里的「完成状态」和「学习时长」两列：

| 完成状态 | 学习时长 | 真实原因 | 属于哪类 |
|---|---|---|---|
| ✅ 已完成 | 0 或远小于要求（如 8:37 vs 18:00） | 旧版没有心跳，服务端只按**两次心跳的墙钟差**累加，一次心跳都没有 → 时长 0 | 只改状态 |
| ✅ 已完成 | 正常 | `setscoinfo`（答题记录）失败但 `savescoinfo`（完成状态）成功，平台回「学习数据不正确」 | 状态写了、记录丢了 |
| ⬜ 未完成 | 0 | 会话过期 / 学习票据被别的窗口顶掉 / 命中 `isPausing` 锁定 / 滑块验证 | 什么都没写进去 |

第三种最容易被误判成"工具没跑"，其实日志里会有明确报错。

## 为什么会出现「答题记录空白」

答题记录（`[INTERACTIONINFO]`）和完成状态是**两个独立请求**：

1. `setscoinfo` —— 带 SCORM 数据（含每题作答记录、progress_measure）
2. `savescoinfo160928` —— 只带完成状态与进度

旧版在 `startsco` 之后**立刻**发这两个请求（间隔≈0），服务端判「学习数据不正确」：
- `setscoinfo` 被拒 → 答题记录一条都没有
- `savescoinfo` 照收 → 状态显示"已完成"

结果就是客户看到的：**完成了，但点进去什么记录都没有。**

还有一种正常情况：该小节本身**没有客观题**（纯阅读/视频），这时答题记录本来就为空，平台只记访问与时长 —— 这种不算故障。

## v3.8 怎么处理

- `startsco` → 真实等待（心跳 20~32s）→ `setscoinfo` → `savescoinfo`，三段之间留足时间，不再触发"学习数据不正确"
- 两个请求**分别判定** `way1` / `way2`，任一失败会重试一次，仍失败如实报错，不会"假装成功"
- 提交后回读 `useSeconds`，日志逐节打印：`[L2] m-3-3-8 way1 ✓ way2 ✓ +61s`
- 学时不足 95% 时提交"未完成 + 真实进度"，不再谎报完成

## 客户自查三步

1. **看日志**：每节是否都有 `way1 ✓ way2 ✓`，后面跟的秒数是否为正
2. **看时长**：刷新课时列表，该节"学习时长"是否增长（有延迟，等 1~2 分钟再刷）
3. **看回读**：日志里"回读"那一行的数字应等于或略大于提交前

三步都过 → 记录是真写进去了；卡在任何一步，日志里会有具体原因（会话过期 / 票据冲突 / 闸门 / 数据不正确）。

## 给客户的回复话术

> 旧版本之前只改了"完成"标记，没写学习记录，所以点进去是空的 —— 这是我们上一版的缺陷，已经修了。
> 现在这版每节课都会真实计时、提交后自动回读校验，日志里能看到每节加了多少秒。
> 如果还有哪一节显示空白，把那一节的日志发我，里面会写清楚是会话过期还是被平台拦了。

## 没法避免的边界

- 学时本身不能压缩：服务端只认自己的钟，客户端上报多少都不影响
- 同一个 SCO 的客观题**只能提交一次**，提交错了不可逆
- 平台侧复核与校级处置没有技术规避面，跑得越像真人越安全
